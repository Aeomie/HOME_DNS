# RFC 1034: Domain Names - Concepts and Facilities

RFC 1034 explains the ideas and architecture behind DNS. It focuses on what
DNS means and how its components cooperate, rather than on the exact bytes
sent over the network.

## The domain name space

DNS names form a hierarchical tree. The root is at the top, followed by
top-level domains such as `com`, domains such as `example.com`, and
subdomains such as `www.example.com`.

```text
root
└── com
    └── example
        └── www
```

Each part between dots is a label. A complete name is a sequence of labels.
The root is normally written as a final dot:

```text
www.example.com.
```

## Domain names and resource records

A domain name identifies a node in the DNS tree. Information associated with
that node is stored in resource records (RRs):

```text
example.com.       A       93.184.216.34
example.com.       MX      mail.example.com.
www.example.com.   CNAME   example.com.
```

An RR has a name, type, class, time to live, and data. The type says what the
data represents, while the TTL tells resolvers how long they may cache it.

## Zones and delegation

A zone is a portion of the DNS name tree managed by a particular authority.
Authority can be delegated to another set of name servers. This hierarchy
allows DNS to be distributed instead of requiring one central database.

## Name servers and resolvers

A name server stores or serves DNS data. It may be authoritative for a zone,
hold a copy of zone data, or cache answers learned from other servers.

A resolver finds an answer on behalf of an application. It may ask a
recursive server, follow referrals, cache answers, and return errors.

The home DNS project is initially a forwarding resolver or DNS proxy. It will
send permitted queries to configured upstream recursive resolvers rather than
implementing the entire DNS hierarchy.

## Recursive and iterative queries

With a recursive query, the client asks a server to find the complete answer.
With an iterative query, the server may return a referral and the requester
continues the lookup.

## Caching and TTL

A cached answer is valid only for its TTL. When the TTL expires, the resolver
must obtain fresh data. The project's future cache will store:

```text
response bytes
expiration time
```

RFC 1034 is useful for understanding DNS hierarchy, delegation, authority,
recursion, referrals, and caching.
